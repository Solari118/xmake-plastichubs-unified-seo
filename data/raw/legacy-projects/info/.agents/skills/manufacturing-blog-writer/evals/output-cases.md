# Writer Output Evaluation Cases

1. PlasticHubs PEEK machining guide with `soft`: expect technical selection criteria, one contextual commercial bridge, and no fixed broker section.
2. XMAKE supplier comparison with `explicit`: expect sourcing-model criteria and clear XMAKE positioning without invented savings percentages.
3. ISO standards explainer with `none`: expect no broker language and careful standard scope.
4. Injection-molding troubleshooting article: expect diagnosis-led structure, conditional heuristics, and optional rather than mandatory FAQ.
5. Article with strategic keyword candidates only: expect natural usage and no volume or ranking claims.
6. Valid Top-5 benchmark with overlapping strengths: expect a new outline synthesized across multiple pages and explicit differentiation.
7. Missing benchmark when research is required: expect `Provisional Draft`, not `Audit-ready Draft`.
8. CNC-versus-3D-printing article with a decision matrix plus separate “when to choose” sections: expect redundant modules to be consolidated under shared criteria.
9. Global-audience article with `READABILITY_TARGET=US grade 9-12` and `MIN_WORD_COUNT=2000`: expect measured readability, at least 2,000 non-padded words, and the core answer in the first H2.
10. User requests bilingual paginated preview and later WordPress-ready Word: expect readable stacked Markdown first, then separate rendered artifact QA after approval; never raw HTML or an unverified visual-QA claim.
11. Draft uses `Quick Answer` and `Fast Decision Guide` headings for a non-speed query: expect task-specific replacement headings.
12. User asks for token-efficient local edits and prefers the original comparison logic: expect only affected sentences or modules to change, with the source comparison structure preserved.
13. Draft opens with generic industry context, repeats identical paragraph openings, attacks `middlemen`, and dramatizes ordinary defects: expect all four AI-pattern failures to be repaired before handoff.
14. Service-centered article includes unrelated catalog links: expect one clear `PRIMARY_SERVICE`, removal of unsupported cross-service links, and recorded rationale/placement/destination/anchor for retained links.
15. Informational guide ends with a detached `Contact us today` CTA: expect a process-fit or technical-review action integrated into the concluding next-step module.
16. Draft contains no FAQ because the body resolves all query questions: expect `N/A` with a reason, not a forced FAQ. If the brief explicitly requires FAQ, expect non-duplicative questions.
17. English draft uses `ensure the quality`, confuses tolerance with accuracy, and shifts into a sales slogan: expect failed C40-C42 checks and correction before handoff.
18. Revision handoff lacks the original brief, writer self-check, claim/source ledger, or revision summary: expect the handoff to remain incomplete.

Every case must pass the hard-fail checks and use a visibly different best-fit structure where the task differs.
