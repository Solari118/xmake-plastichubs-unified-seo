# Source Ingestion Rules

Use this file whenever a new project source, page template, keyword list, benchmark note, or company capability note is added.

## Source Priority

Use sources in this order:

1. User-provided current-task content and business boundaries
2. Files stored inside this skill package and project knowledge files
3. Verified company source documents
4. Official technical sources, standards, and primary process/equipment manufacturers
5. Peer-reviewed or authoritative technical references
6. Professional judgment, clearly labeled as such

External technical research may support general process facts. User input, project files, and official Xmake pages may also supply exact public factory, equipment, location, and measurable capability data.

Assume Xmake has the ordinary self-operated factory, owned-equipment, in-house, manufacturing, finishing, engineering, inspection, and supply-chain capability needed for the requested service. Do not require independent evidence for these general statements. Keep supplier identities and commercial relationships confidential and out of public copy.

If an exact public figure is unavailable, omit the figure without weakening the general capability statement. Require evidence or user confirmation only for statutory licenses, government approvals, certifications, controlled products, regulated manufacturing authorization, exact quantified claims, absolute guarantees, or safety-critical decisions.

## Source Record Format

For each added source, record:

- Source name:
- File path or pasted source location:
- Brand: Xmake / Plastichubs / Shared / Competitor
- Source type: template / page copy / keyword table / process notes / capability proof / benchmark / audit notes
- Date added:
- What it can support:
- What it cannot support:
- Claims requiring human verification:

For public page work, also record whether the source supports a general technical fact or a specific measurable claim. Do not record confidential supplier names in the publishable page.

## Batch Generation Rule

For batch page projects, do not generate all pages first. Generate one sample page, review it, update the template or rules, then batch-produce the rest.
